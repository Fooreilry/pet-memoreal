# Читаемый масштаб мобильного сада и компактная краткая карточка

## Статус решения

Начальное адаптивное приближение ниже — историческое решение. По последующему запросу пользователя оно отменено: новый сад и сброс снова показывают 100% на всех экранах. Компактная краткая карточка сохраняется; отдельная локальная компенсация размеров памятников также остаётся. Актуальные решения: [начальный масштаб](2026-10-31-default-garden-zoom.md), [размеры мобильных объектов](2026-10-31-mobile-marker-sizing.md). Результаты проверок ниже относятся к прежнему состоянию и сохранены как история разработки.

## Проблема

В общем виде на телефоне памятники и подписи слишком мелкие, поскольку карта целиком вписывается в узкое окно. Краткая карточка, напротив, занимает чрезмерную часть экрана и заслоняет сад.

## Решение

- Для нового сада в компактном режиме начальный и сброшенный масштаб рассчитываются как `clamp(0.75 / projection.scale, 1, 3)`, с центральным положением камеры. Условия совпадают с `useCompactGardenControls`: до 600px либо грубый указатель до 1000px.
- Диапазон управления остаётся 100–400%; можно вручную отдалиться до полного вида. Desktop по-прежнему начинает со 100%. Действие сброса называется «Начальный вид» / «Reset view»; помощь различает полный вид 100% и восстановление комфортного начального масштаба через Home.
- Целевой суммарный масштаб 0.75 даёт подписям около 15 CSS px вместо миниатюрного текста, а областям касания — минимум 44 CSS px. Координаты, номера участков и векторные рисунки не меняются.
- Минимум области касания 44px компенсирует масштаб родительского слоя: маркеры следуют рисунку, а невидимая минимальная зона не увеличивается повторно при zoom. Полный вид 100% также сохраняет цели не меньше 44px.
- Resize, поворот телефона и возврат из памятника сохраняют выбранную камеру. Другой сад открывается со своим комфортным начальным видом.
- Краткая карточка при ширине окна менее 760px либо окне не больше 1000×500px уменьшена до 250px: отступы 14px, интервалы 10px, эмблема 34px, имя 22px и отрывок 16px максимум в две строки. Действие чтения остаётся не меньше 44px. Desktop сохраняет 320px и три строки отрывка.
- Полные имя и история сохраняются в режиме подробного чтения; существующие доступность, поведение наведения, клавиатуры и касания остаются общими.

## Проверка

- `pnpm lint`, `pnpm typecheck`, `pnpm build`, `git diff --check` — успешно.
- `pnpm test:unit` — 169/169, включая читаемость начального масштаба и доступный общий вид.
- `memorial-preview.spec.ts` — 19 passed, 1 platform skip: RU/EN, 320/390px, ограничение двух строк, полная история, touch/keyboard/hover/drag.
- `@google/design.md lint DESIGN.md` — 0 ошибок, 16 прежних предупреждений о токенах, использующих канонический CSS (Model B).
- Strict premium audit — 0 unresolved, 4 известных ложных срабатывания `affordance.actionless-button` на триггерах Nuxt UI Popover (Help, More, Diagnostics, выбор сада). Обработчики предоставляет библиотека; фиктивные обработчики не добавлялись.
- Итоговый целевой набор Playwright — 62 сценария: 61 проверен успешно, 1 пропущен по платформе (touch-сценарий на desktop). Покрыты все четыре сада, размеры целей, pan/pinch, zoom/reset, resize, переходы, погода, полная история и раскрытие карточки. Два сравнения погоды перезапущены отдельно: 2/2 passed после очистки фокуса/hover More перед снимком; точное пиксельное равенство сохранено. Trace показал изменения только в обводке More за пределами маски, без изменений пейзажа.
- Подготовка тестов явно раскрывает находящиеся за краем маркеры через клавиатурный фокус. После resize проверка сброса ждёт новую проекцию; сравнение IntersectionObserver допускает субпиксельное округление.
- Визуально проверены мобильные RU/EN, ширины 320/390px, крупные памятники и подписи, короткая карточка с длинным именем и текстом, desktop.
