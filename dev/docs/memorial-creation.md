# Создание места памяти

## Сценарий

Откройте `/gardens`, выберите сад и нажмите «+» на свободном участке. Откроется отдельная страница `/memorials/new?garden=lake&place=3`; выбранные сад и номер места закреплены. Гость сначала входит в аккаунт, затем возвращается на эту страницу с тем же выбором. Параметры сохраняются при переходе к регистрации и в ссылке подтверждения почты.

Создание и редактирование используют общую страничную оболочку `MemorialFormPage` и компонент `MemorialCreationForm`. Окна создания поверх сада больше нет. Старые ссылки `/gardens?garden=lake&create=3` перенаправляют на страницу создания, сохраняя сад и место. Отмена или ссылка назад возвращают к выбранному саду без записи в базе.

Поля: имя (1–80 символов), вид животного, год рождения и ухода (целые, от 1900 до текущего года, уход не раньше рождения), история (1–5000 символов) и анонимность. Выбранные на карте сад и место показаны без возможности переноса. При прямом входе на `/memorials/new` без места можно выбрать сад; сервер выделит свободный участок. Неверные явные параметры показывают недоступность вместо скрытого выбора другого места; занятый участок предлагает открыть существующую карточку. Пробелы по краям убираются. Все создаваемые места **публичные**; форма сообщает об этом до сохранения. Чекбокс «Остаться анонимным» скрывает имя создателя; по умолчанию у нового места отображается имя из профиля. Выбор сохраняется при ошибке отправки. Фотографии пока не поддерживаются.

Вид животного выбирается в обязательном списке с поиском. Общий справочник `shared/pet-species.ts` содержит 20 видов, включая шиншиллу, хорька, змею, ящерицу, аксолотля и паука, и вариант «Другой питомец» (`pet`). Поддерживаются клавиатура и сенсорный экран. Для каждого вида используется отдельный локальный значок в списке, подсказке и полной истории; `PetSpeciesIcon` объединяет Lucide и небольшие SVG без отдельных загрузок изображений.

После успешного POST очищаются кеши карты и кабинета, затем открывается `/gardens?garden=lake&memorial=<uuid>` с развёрнутой карточкой сохранённого питомца. Такой же переход доступен в списке «Мои места памяти» в кабинете. Обновление страницы и гостевой просмотр снова читают запись из PostgreSQL. При ошибке форма сохраняет введённый текст.

## Хранение и размещение

Миграция `0002_round_susan_delgado.sql` добавляет таблицу `memorials` и постоянные записи четырёх садов. Есть внешние ключи на владельца и сад, проверки полей и уникальные индексы `(garden_id, place)` и `(owner_id, request_id)`. Существующий сад `common` сохранён. `db:seed` можно выполнять повторно.

Миграция `0005_chubby_starfox.sql` добавляет `is_anonymous`. Старые записи получают `true`, чтобы не раскрывать имена задним числом; для новых записей значение по умолчанию — `false`. Анонимное место остаётся закреплённым за владельцем и отображается в его кабинете.

Миграция `0007_pet_species.sql` добавляет `species` с проверкой допустимых значений и значением `pet` для прежних записей. Вид старого питомца можно уточнить при редактировании. Локально выполните `corepack pnpm db:migrate`; перед выкладкой новой версии на Vercel примените эту миграцию к Neon через `corepack pnpm db:migrate:demo` с настроенным `.env.vercel`.

Сервер блокирует строку выбранного сада внутри транзакции и сохраняет запись в указанном `place`. Если другой запрос успел занять его, возвращается 409 `Place occupied`: страница остаётся открытой с черновиком и предлагает вернуться в сад для выбора свободного места. В запросе без `place` сервер выбирает первое свободное обычное место. Вместимость сцен: луг — 12, озеро — 10, роща — 16, холм — 14. Четыре слота в каждом саду отведены для примеров (`shared/gardens.ts`); новые записи туда не попадают. Соответственно, для новых пользовательских мемориалов доступны 8/6/12/10 слотов. Существующие реальные записи, включая ранее занятые слоты примеров, сохраняют приоритет и не перемещаются. При заполнении доступных мест возвращается 409 `Garden full`.

Форма использует UUID запроса, который сохраняется при повторной попытке. Повтор того же тела с тем же ключом возвращает уже созданный мемориал, включая заполненный сад. Изменённое тело, в том числе другой выбор анонимности, с использованным ключом отклоняется. Уникальный индекс также защищает от одновременных запросов.

## API

| Запрос | Доступ и результат |
| --- | --- |
| `POST /api/memorials` | Подтверждённый пользователь, JSON и Origin приложения. Владелец берётся из сессии; необязательное `place` проверяется сервером или выбирается автоматически. `isAnonymous` — boolean, по умолчанию `false`. |
| `GET /api/gardens/:slug/memorials` | Публичные данные только выбранного сада. |
| `GET /api/memorials/mine` | Список текущего владельца; гостю — 401. |
| `GET /api/memorials/:id` | Данные формы, включая `isAnonymous`, только подтверждённому владельцу. Чужая или отсутствующая запись — 404. |
| `PATCH /api/memorials/:id` | Подтверждённый владелец, JSON и Origin приложения; обновляет только содержимое и анонимность существующей записи. |

Ответы содержат `id`, `gardenId` (slug), `place`, `name`, `born`, `died`, `story`, `source: saved`, выбранный `species` и `creatorName`. Последнее поле содержит текущее имя из профиля либо `null` для анонимного места. SQL-запрос исключает имя анонимного автора из результата; скрытие работает на сервере. Фамилия, email, ID владельца и ключ запроса не публикуются. Полная карточка показывает имя или «Анонимно»; у демонстрационных мест автор не указывается. Ответы не кешируются. Схема Zod находится в `shared/memorials.ts`; лишние входные поля отклоняются. Текст отображается как текст, без `v-html`.

## Редактирование

Владелец открывает своё место памяти в саду и нажимает кнопку с карандашом в полной карточке. На `/memorials/:id/edit` загружаются текущие значения. Страница имеет ту же компоновку и поля, что создание; отличаются заголовок, заполненные значения и действие сохранения. Можно изменить имя, вид животного, оба года, историю и чекбокс анонимности. Сад и номер места остаются закреплёнными; форма не переносит памятник.

Общая форма переключает схему и метод отправки в режим редактирования. `PATCH` требует все шесть полей: `name`, `species`, `born`, `died`, `story`, `isAnonymous`. `POST` также требует `species`; неизвестные значения отклоняются. Поля `ownerId`, `gardenId`, `place`, `requestId` и любые другие дополнения в PATCH отклоняются. Условия длины текста и годов совпадают с созданием. Право проверяется в SQL по ID записи и владельцу из сессии; роль admin сама по себе не даёт доступа к чужой записи.

Публичное поле `canEdit` содержит только вычисленное для текущего посетителя разрешение. У гостей и других пользователей оно равно `false`; ID автора для этого не передаётся. Анонимный владелец сохраняет кнопку редактирования. Приватный GET возвращает `isAnonymous` для заполнения формы; публичные ответы это поле не раскрывают.

После успешного сохранения очищаются кеши карты, списка кабинета и приватной формы. Пользователь возвращается в тот же сад с открытой обновлённой карточкой. Отмена возвращает к прежней записи, а ошибка оставляет черновик и выбранную анонимность. Ошибки загрузки предлагают повтор; чужая или удалённая запись показывает недоступность без формы. Изменения сохраняются в прежней строке PostgreSQL без миграции и без смены владельца, сада, места или ключа создания.

## Запуск и проверка

```powershell
corepack pnpm db:migrate
corepack pnpm db:seed
corepack pnpm db:test
corepack pnpm lint
corepack pnpm typecheck
corepack pnpm build
corepack pnpm exec playwright test memorials.spec.ts memorial-edit.spec.ts
```

Для браузерных тестов нужен локальный PostgreSQL. Полный набор авторизации также использует Mailpit. Playwright создаёт и удаляет отдельную временную базу. Фикстуры проверенных пользователей создаются только в этой базе; вход, API и сохранение настоящие. Тесты визуального прототипа подменяют только чтение мемориалов пустым ответом, чтобы создавать места параллельно и не менять ожидания демосцен.
