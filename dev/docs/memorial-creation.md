# Создание места памяти

## Сценарий

Откройте `/ru/gardens` / `/en/gardens`, выберите сад и нажмите «+» на свободном участке. Форма откроется в окне поверх сада; выбранные сад и номер места закреплены. Гость сначала входит в аккаунт, затем возвращается к `?garden=lake&create=3` с открытой формой. Выбор сохраняется при переходе к регистрации и в ссылке подтверждения почты. Кнопка создания в кабинете ведёт к карте. Старые страницы `/ru/memorials/new` / `/en/memorials/new` продолжают работать.

Поля: имя (1–80 символов), год рождения и ухода (целые, от 1900 до текущего года, уход не раньше рождения), история (1–5000 символов) и один из четырёх садов. Пробелы по краям убираются. Все создаваемые места **публичные**; форма сообщает об этом до сохранения. Чекбокс «Остаться анонимным» скрывает имя создателя; по умолчанию у нового места отображается имя из профиля. Выбор сохраняется при ошибке отправки. Фотографии и редактирование не входят в этот шаг.

После успешного POST открывается `/ru/gardens?garden=lake&memorial=<uuid>` с историей сохранённого питомца. Такой же переход доступен в списке «Мои места памяти» в кабинете. Обновление страницы и гостевой просмотр снова читают запись из PostgreSQL. При ошибке форма сохраняет введённый текст.

## Хранение и размещение

Миграция `0002_round_susan_delgado.sql` добавляет таблицу `memorials` и постоянные записи четырёх садов. Есть внешние ключи на владельца и сад, проверки полей и уникальные индексы `(garden_id, place)` и `(owner_id, request_id)`. Существующий сад `common` сохранён. `db:seed` можно выполнять повторно.

Миграция `0005_chubby_starfox.sql` добавляет `is_anonymous`. Старые записи получают `true`, чтобы не раскрывать имена задним числом; для новых записей значение по умолчанию — `false`. Анонимное место остаётся закреплённым за владельцем и отображается в его кабинете.

Сервер блокирует строку выбранного сада внутри транзакции и сохраняет запись в указанном `place`. Если другой запрос успел занять его, возвращается 409 `Place occupied`, введённый текст остаётся в форме. В запросе без `place` сервер выбирает первое свободное обычное место. Вместимость сцен: луг — 12, озеро — 10, роща — 16, холм — 14. Четыре слота в каждом саду отведены для примеров (`shared/gardens.ts`); новые записи туда не попадают. Соответственно, для новых пользовательских мемориалов доступны 8/6/12/10 слотов. Существующие реальные записи, включая ранее занятые слоты примеров, сохраняют приоритет и не перемещаются. При заполнении доступных мест возвращается 409 `Garden full`.

Форма использует UUID запроса, который сохраняется при повторной попытке. Повтор того же тела с тем же ключом возвращает уже созданный мемориал, включая заполненный сад. Изменённое тело, в том числе другой выбор анонимности, с использованным ключом отклоняется. Уникальный индекс также защищает от одновременных запросов.

## API

| Запрос | Доступ и результат |
| --- | --- |
| `POST /api/memorials` | Подтверждённый пользователь, JSON и Origin приложения. Владелец берётся из сессии; необязательное `place` проверяется сервером или выбирается автоматически. `isAnonymous` — boolean, по умолчанию `false`. |
| `GET /api/gardens/:slug/memorials` | Публичные данные только выбранного сада. |
| `GET /api/memorials/mine` | Список текущего владельца; гостю — 401. |

Ответы содержат `id`, `gardenId` (slug), `place`, `name`, `born`, `died`, `story`, `source: saved`, `species: pet` и `creatorName`. Последнее поле содержит текущее имя из профиля либо `null` для анонимного места. SQL-запрос исключает имя анонимного автора из результата; скрытие работает на сервере. Фамилия, email, ID владельца и ключ запроса не публикуются. Полная карточка показывает имя или «Анонимно»; у демонстрационных мест автор не указывается. Ответы не кешируются. Схема Zod находится в `shared/memorials.ts`; лишние входные поля отклоняются. Текст отображается как текст, без `v-html`.

## Запуск и проверка

```powershell
corepack pnpm db:migrate
corepack pnpm db:seed
corepack pnpm db:test
corepack pnpm lint
corepack pnpm typecheck
corepack pnpm build
corepack pnpm exec playwright test memorials.spec.ts
```

Для браузерных тестов нужен локальный PostgreSQL. Полный набор авторизации также использует Mailpit. Playwright создаёт и удаляет отдельную временную базу. Фикстуры проверенных пользователей создаются только в этой базе; вход, API и сохранение настоящие. Тесты визуального прототипа подменяют только чтение мемориалов пустым ответом, чтобы создавать места параллельно и не менять ожидания демосцен.
