# Разворачивание сада в пределах окна браузера

## Проблема

Кнопка запрашивала native Fullscreen API для всего сайта, скрывая интерфейс браузера. Требуется заполнить картой только окно браузера.

## Решение

- Состояние режима принадлежит странице gardens, кнопка canvas только переключает его.
- При разворачивании скрывается шапка, снимаются внешние отступы и скругления garden-stage. Сад заполняет 100dvh, включая контролы, заголовок и переходы между садами.
- Удалены requestFullscreen/exitFullscreen, проверка поддержки и сообщения об ошибках API. Обе локали называют действие разворачиванием карты на окно.
- Размер canvas меняет существующий ResizeObserver; мир, масштаб и сцена сохраняются.
- Повторное нажатие и Escape восстанавливают обычную компоновку. Открытые диалоги/меню получают первый Escape; после сворачивания фокус возвращается кнопке.
- Соседние сады сохраняют режим, обзор четырёх садов и переход на другую страницу сбрасывают его.
- Во время загрузки следующего сада и при ошибке остаётся кнопка сворачивания: на телефоне можно вернуть шапку без клавиши Escape.

## Проверки

- `test:unit`: 91 проверка пройдена. `lint`, `typecheck`, `build`: успешно.
- `garden-shell.spec.ts`: все 16 сценариев desktop/mobile пройдены. Проверены размеры canvas и drawing buffer, отсутствие вызовов Fullscreen API, сохранение мира и масштаба при развороте и смене ориентации, Escape, карточки, меню, создание, загрузка и ошибка API.
- Дополнительные сценарии `gardens.spec.ts`: 37 пройдены, 2 пропущены по типу устройства. Длинный desktop-сценарий анимаций трёх садов превысил общий лимит 30 секунд при параллельном запуске; изолированный повтор с бюджетом 60 секунд прошёл за 21,3 секунды. Проверки поведения не ослаблялись.
- Визуально проверен развёрнутый сад: карта и HUD заполняют viewport без шапки, внешних отступов и скругления.
