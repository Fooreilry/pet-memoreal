# Лендинг только для гостей и базовые роли

## Задача

Не показывать лендинг авторизованному пользователю: переход на главную должен сразу открывать обзор четырёх садов. Зафиксировать роли `user` и `admin` как основу будущего разделения доступа; на текущем этапе обе роли используют одинаковый интерфейс.

## Решение

- Middleware `landing` проверяет подтверждённую сессию через `/api/me` при SSR и клиентских переходах. Гостю остаётся лендинг, пользователь попадает в `/ru/gardens` или `/en/gardens`. Во время гидрации гостевой страницы повторная проверка не нужна.
- Главная сохраняет информационную компоновку, но предварительная генерация отключена: сервер должен проверить cookie до выдачи HTML. Ответы главной и перенаправления используют `private, no-store`.
- `shared/roles.ts` задаёт роли `user`/`admin`, их тип и общий конфиг Better Auth для сервера и клиента. `/api/me` возвращает роль из подтверждённой сессии. Регистрация по умолчанию создаёт `user`; изменение роли через регистрацию и профиль запрещено.
- Миграция `0006_smiling_sharon_carter.sql` добавляет CHECK для допустимых ролей без изменения существующих записей. Применена к проверенной локальной PostgreSQL; удалённая Neon не затрагивалась. Дополнительные возможности администратора пока не вводятся.
- Подготовительные тестовые входы и UI-сценарий авторизации учитывают общий локальный IP: при 429 ожидают `X-Retry-After` и повторяют запрос один раз. Производственные лимиты не изменены. Для фикстур ожидание имеет отдельный таймаут, ошибки кроме 429 не повторяются.
