# Явная запись диагностики и контрольные прогоны

## Проблема

Доступность инструмента смешивалась с записью, а открытие панели меняло режим. Долговременная средняя частота выглядела текущей. Остановка, изменение условий и просмотр завершённых результатов не имели отдельных состояний.

## Изменения

- Флаг предоставляет инструмент, но коллектор начинает в `idle` с `recording=false`. Start/Stop, видимость и panel/collect разделены; обычный лимит анимации остаётся 30.
- Изменение FPS, режима, seed, эффектов, размеров viewport или видимости во время ручной записи архивирует run и продолжает его с новыми условиями. Завершённые отчёты заморожены; локальный архив ограничен 12 записями.
- Schema 2 сохраняет условия начала, фактический `observedContext`, причину завершения, результат проверки и происхождение ввода. Отдельные результаты скачиваются по run ID.
- Текущая частота использует непрерывное активное окно до 2 секунд; средняя учитывает весь run. Пауза и скрытая вкладка разрывают окно.
- UI запускает общий протокол: текущий/все сады, 3 секунды прогрева, 15 секунд записи, 3 обычных повтора. Есть фазы, отмена, восстановление настроек и невалидные результаты. UI-ввод помечается синтетическим; внешний Playwright использует доверенный ввод.
- Панель использует существующие Nuxt UI primitives и токены. Значения обновляются только при открытой panel-версии с частотой 2 Гц; per-frame Vue-обновлений нет.
- Добавлены UI-проверки записи, остановки, разделения условий, результатов и отмены. Runtime-тест проверяет, что при `recording=false` рендер продолжается без измерительных callback и чтения контекста.
- Непрерывная камера и синтетический ввод используют существующий ticker. Native pointer capture применяется только к доверенным событиям: синтетический pointer ID не зарегистрирован браузером. Во время UI-прогона автоматическое outside-dismiss отключено; Close/Cancel/Escape отменяют прогон, а обычные Select/Popover сохраняют своё поведение.

## Проверка

- Unit — 168/168, lint, typecheck и production build прошли. Unit-воспроизведение 600 секунд по 60 ticks/s + 10 секунд по 30 показывает текущие 30 и средние 59.508.
- Production diagnostics — 14/14; финальные FPS/mode split, полный камерный прогон и pointer/cancel повторно прошли 3/3 после интеграции. Проверены idle, отдельные настройки/видимость, замороженные JSON, hidden/pause, API/preparation, resize и pending-run reset. Есть реальный UI-прогон 3×15 секунд после 3-секундного прогрева.
- Панель и вложенные списки проверены на 1440/390/320px, клавиатура/Escape и цели 44px; PNG desktop/mobile просмотрены. Design lint: 0 ошибок, 16 предупреждений CSS-потребителей Model B. Статический аудит: 0 unresolved; 3 известные ложные ошибки на Nuxt UI Popover triggers, реальные действия проверены браузером.
- Обычные camera/loading/preview controls — 12/12 desktop/mobile; 2 платформенных сценария намеренно skipped. `playwright.ui.config.ts` явно выключает диагностику независимо от локального `.env`.
- Первый внешний запуск остановлен после 13 корректных результатов: фиксированная очередь из 450 CDP-команд могла растянуть ввод за пределы 15 секунд на медленном рендере. Драйвер теперь следует фактическому времени, пропускает просроченные позиции и сохраняет отправленные/обработанные события. Проверяются все 8 wheel steps; browser trusted-input case прошёл за штатное окно, чистый scheduler покрыт 3 unit-тестами. Итоговый набор получен отдельным повторным запуском.
- Итоговый внешний baseline завершён за 15.9 минуты: 53/53 valid, 4 первых открытия, 48 steady-измерений и 40 переходов. Schema 2, collect, seed 424242, DPR 1, лимит 30; steady содержит только активные измерения без generation/ready. Все 12 input-прогонов доставили и обработали 8 wheel events, 26–37 pointer moves. Ввод занимал 15.10–15.45 секунды с допустимым завершением одной уже отправленной команды; очереди догоняющих перемещений нет.
- Непрерывная камера зафиксировала 70–94 изменения за каждый run. Максимальная сохранённая выборка — 377 при capacity 2048. Учтённые ресурсы одинаковы во всех 10 циклах: meadow 101, lake 81, grove 99, hill 98; ready renderTextures=0. Это проверка графа сцены, а не доказательство отсутствия GPU/driver leaks.
- Baseline: `dev/benchmarks/results/2026-10-30T13-00-14-234Z-fps30-0fe3f938/summary.json`. Полная независимая post-validation: `test-results/diagnostics-v2-validation.json`; лог `test-results/diagnostics-v2-baseline-final.log`. Более ранняя папка `2026-10-30T12-47-41-356Z-fps30-c746e4ca` содержит прерванную попытку и не является итоговым baseline. Предыдущая schema 1 не сопоставима с новой нагрузкой камеры.
- Среда итогового замера: Headless Chromium 153, WebGL2/ANGLE/Vulkan SwiftShader. Данные характеризуют этот программный renderer и не являются результатами аппаратного телефона.
- После последней сборки повторно прошли layout и manual-recording с проверкой `configuration.panelVisible` (2/2). Снимки сохранены в `test-results/diagnostics-v2-final-evidence/`, включая desktop/390px/320px и вложенный FPS listbox. Тестовые серверы остановлены.
