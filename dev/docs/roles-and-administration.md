# Роли и администрирование

Роль хранится в `auth_user.role`. Все новые регистрации получают `user`. Права вычисляются на сервере из роли; браузер не может передать собственные разрешения. Контракт и проверки находятся в `shared/roles.ts`, ограничения допустимых ролей — в миграции `0008_role_permissions.sql`.

## Матрица доступа

| Роль | Админка | Экспериментальные функции | Конфигурирование |
| --- | --- | --- | --- |
| `admin` | 3 | `true` | 3 |
| `developer` | 1 | `true` | 3 |
| `manager` | 2 | `false` | 0 |
| `user` | 0 | `false` | 0 |

Уровни админки: `0` — нет доступа, `1` — просмотр, `2` — просмотр и редактирование, `3` — также добавление и удаление. Назначать роли может только `admin`, независимо от других разрешений. Изменить собственную роль через админку нельзя.

Уровни конфигурирования: `0` — запрещено, `1` — только собственные объекты, `2` — все сады, `3` — все сады, памятники и будущие настройки. Уровни 1 и 2 зарезервированы для дальнейшего расширения ролей. Сейчас право уровня 3 разрешает редактировать любой сохранённый памятник через обычную форму. У manager это действие разрешено правом редактирования в админке. Владелец всегда может редактировать свой памятник.

`experimentalFeatures` — логический флаг доступа к будущим экспериментальным функциям. Уже опубликованные погодные эффекты остаются доступны пользователям; редактор настроек погоды этим этапом не добавляется. Новые функции должны проверять флаг из `/api/me`, а закрытые серверные операции — роль подтверждённого пользователя. Одного скрытия кнопки недостаточно.

## Первый администратор

Локальный игнорируемый `.env` содержит `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_NAME`, `ADMIN_SURNAME`. Пароль должен содержать 16–128 символов. Данные входа не добавляются в документацию или Git.

```powershell
corepack pnpm db:migrate
corepack pnpm db:seed
# Или создать только администратора, не заполняя справочники:
corepack pnpm db:admin
```

`db:seed` создаёт администратора, если заданы обе обязательные переменные `ADMIN_EMAIL` и `ADMIN_PASSWORD`. Без них заполняются только справочные сады. Отдельная команда `db:admin` требует эти настройки. Пользователь сразу подтверждён и входит через обычную форму `/login`. Пароль хешируется совместимым с Better Auth способом; открытый пароль хранится только в локальном env-файле.

Повторный запуск сохраняет существующие пароль, имя и фамилию администратора. Изменение `ADMIN_PASSWORD` само по себе пароль в базе не меняет; для смены используйте восстановление пароля. Если адрес занят обычным пользователем, неподтверждённым аккаунтом или аккаунтом без пароля, команда откажет, сохранив его данные.

Для Neon добавьте отдельные `ADMIN_*` в игнорируемый `.env.vercel`, затем выполните `db:migrate:demo` и `db:admin:demo`. Применение миграции само по себе не создаёт пользователя. Эти переменные нужны командам заполнения, а не приложению в Vercel; секреты администратора не следует передавать в публичный runtime config. Локальные действия не меняют облачную базу.

## Интерфейс и API

В профиле привилегированных ролей появляется вкладка «Администрирование» (`/admin`). Она показывает пользователей, занятость садов и памятники. Данные пользователей и памятников выдаются страницами по 20 записей, новые первыми. manager может открыть форму редактирования; admin также открыть создание и удалить памятник после подтверждения. Форма создания сохраняет авторство вошедшего пользователя.

- `GET /api/admin/overview?usersPage=1&memorialsPage=1` — уровень админки от 1.
- `PATCH /api/admin/users/:id` с `{ "role": "manager" }` — только admin.
- `DELETE /api/admin/memorials/:id` — уровень админки 3.
- `GET/PATCH /api/memorials/:id` — владелец, право редактирования админки или конфигурирование 3.

Ответы не кешируются. Записывающие запросы проверяют origin; JSON-запросы принимают только разрешённые поля. Сервер повторно читает актуальную роль из БД, поэтому понижение прав действует без нового входа. В публичной карте анонимный автор по-прежнему скрыт; административный API доступен только привилегированным ролям и содержит владельцев записей. Пароли, токены и сессии он не возвращает.

Следующие отдельные задачи: журнал административных изменений и редактор конфигурации садов. Для них не требуется расширять текущую матрицу ролей.

## Поведение интерфейса

Локальная навигация ведёт к пользователям, садам и памятникам. Индикатор сада показывает фактическую занятость, а не прогресс загрузки. Пагинация остаётся в URL; при обновлении видны предыдущие данные с состоянием загрузки. Ошибка сохраняет снимок для чтения, блокирует запись и предлагает повтор. Удаление последней записи на странице возвращает к допустимой предыдущей странице.

Выбор новой роли — черновик. Перед PATCH диалог показывает пользователя, старую/новую роль и последствия доступа; первичный фокус стоит на отмене. Несохранённый выбор роли защищён при уходе, смене страницы пользователей и явном обновлении. Пагинация памятников сохраняет выбранные роли, в том числе при автоматическом возврате на предыдущую страницу после удаления. Диалоги сохраняются при ошибке, позволяя повторить запрос. Это не меняет серверные ограничения матрицы прав.
