# Роли, права и начальный администратор

## Задача

Расширить прежние роли user/admin до user/manager/developer/admin, предоставить независимые права на админку, экспериментальные функции и конфигурирование. Создать первого администратора из локального env-файла.

## Решение

- Матрица в `shared/roles.ts`: admin 3/true/3, developer 1/true/3, manager 2/false/0, user 0/false/0. Неизвестные роли не получают привилегий.
- Согласованная с пользователем шкала конфигурирования: 0 — нельзя, 1 — свои объекты, 2 — все сады, 3 — все объекты. Управление ролями выделено в действие только admin.
- Миграция 0008 расширяет CHECK таблицы auth_user. Начальный подтверждённый администратор создаётся идемпотентно через db:seed/db:admin с Better Auth hashPassword. Существующие пользовательские адреса не повышаются и пароли не сбрасываются.
- В игнорируемый .env добавлены ADMIN_*. Локальная миграция применена, администратор создан. Облачная база не затрагивалась.
- /api/me возвращает вычисленные права. Сервер читает текущую роль для каждого защищённого запроса; старые сессии не сохраняют отозванный доступ.
- Назначение ролей сериализовано транзакционной блокировкой с повторной проверкой инициатора. Запрещены понижение собственной роли и удаление последнего администратора через назначение ролей.
- Добавлены вкладка профиля, /admin, пагинация списков, редактирование памятников, подтверждение удаления и назначение ролей только администратором. Приватные ответы no-store; мутации проверяют origin и строгие схемы.
- Конфигурирование 3 уже разрешает редактирование всех памятников. Флаг экспериментальных функций и остальные уровни — основа будущих функций; редактор погоды пока не добавлен.
- Мобильные строки пользователей размещены вертикально без горизонтального переполнения. Это устранило смещение области нажатий при редактировании и подтверждении удаления на эмулируемом телефоне. Проверки используют обычные клики, без force.
