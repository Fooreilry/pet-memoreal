# Письма регистрации через Gmail SMTP

## Что меняется

Пользователь регистрируется с email и паролем, получает письмо подтверждения и при необходимости восстанавливает пароль. Письма отправляет Gmail через существующий Nodemailer. Это настройка доставки писем; вход кнопкой «Продолжить с Google» требует отдельного подключения Google OAuth.

Код уже поддерживает Gmail SMTP. Схему базы и зависимости менять не требуется. Сайт может оставаться на Vercel или работать локально через Cloudflare Tunnel; отправитель — ваш Gmail-адрес.

## 1. Настроить аккаунт Google

1. Выберите отдельный Gmail-аккаунт для писем проекта и войдите в него.
2. В настройках безопасности включите двухэтапную аутентификацию.
3. Откройте [пароли приложений](https://myaccount.google.com/apppasswords).
4. Создайте пароль для приложения с названием `PetMemoreal`.
5. Сохраните выданный пароль в настройках ниже. Если он отображается группами, в значение переменной внесите 16 символов без разделяющих пробелов.

Если раздел недоступен, проверьте двухэтапную аутентификацию и ограничения аккаунта: рабочие аккаунты, Advanced Protection и вход только с аппаратными ключами могут ограничивать пароли приложений. [Справка Google](https://support.google.com/accounts/answer/185833?hl=ru).

## 2. Заменить SMTP-переменные

| Переменная | Значение |
| --- | --- |
| `SMTP_HOST` | `smtp.gmail.com` |
| `SMTP_PORT` | `465` |
| `SMTP_SECURE` | `true` |
| `SMTP_USER` | Полный Gmail-адрес отправителя |
| `SMTP_PASSWORD` | Созданный пароль приложения Google |
| `SMTP_FROM` | Тот же Gmail-адрес, что в `SMTP_USER`; только email |

Скопируйте значения в нужное место:

- **Vercel:** проект → Settings → Environment Variables → Production. Замените все шесть SMTP-переменных Resend, включая хост и имя пользователя. В Value вводится только значение, без имени переменной и внешних кавычек. Затем Deployments → production-деплой → Redeploy.
- **Локальный сервер `corepack pnpm dev`:** `.env`, затем перезапустите сервер. Это заменит Mailpit реальной отправкой для локального приложения.
- **Проверка настроек демо:** `.env.vercel`, чтобы `corepack pnpm deploy:check` проверял того же отправителя, что Vercel. Секреты в Git и переписку не добавляйте.

Параметры SMTP и выбор порта описаны в [Google SMTP](https://developers.google.com/workspace/gmail/imap/imap-smtp).

## 3. Проверить адрес приложения

Для Vercel оставьте `BETTER_AUTH_URL=https://pet-memoreal.vercel.app`, если это постоянный адрес проекта. Для обычной локальной разработки используйте `http://127.0.0.1:3000`. Для настроенного Cloudflare Tunnel укажите его внешний HTTPS-адрес; при смене адреса обновите настройку и перезапустите приложение.

`BETTER_AUTH_SECRET` и подключения Neon при смене SMTP не меняются.

## 4. Проверить доставку

1. При заполненных настройках авторизации и базы выполните `corepack pnpm deploy:check`. Команда проверяет SMTP-соединение и учётные данные без отправки письма.
2. На целевом сайте зарегистрируйте тестовый аккаунт с доступным email.
3. Откройте полученное письмо: отправитель должен совпадать с выбранным Gmail-адресом, ссылка должна вести на целевой сайт.
4. Подтвердите email, войдите, проверьте восстановление пароля.

При `Invalid login` проверьте Gmail-адрес, пароль приложения и отсутствие пробелов. Пароли приложений отзываются при смене основного пароля Google. У Gmail действуют ограничения отправки; этот вариант предназначен для небольшого демо. [Ограничения Gmail](https://support.google.com/mail/answer/22839?hl=ru).
