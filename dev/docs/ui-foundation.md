# Основа интерфейса

Лендинг доступен гостям на `/`: идея проекта, четыре сада, шаги создания места, принципы и вопросы. Основная кнопка ведёт на регистрацию, дополнительная — на вход. Авторизованный пользователь с главной перенаправляется в сады. Создание открывается прямо в саду после нажатия на свободное место; формы предпросмотра на лендинге нет. Язык определяется [по стране](localization.md), адреса страниц одинаковы для русского и английского. Подробности оформления — в [разборе лендинга](landing-design.md).

## Тема и типографика

Тема сочетает кремовые поверхности с тёмными лесными секциями. Фон `#faf5eb`, основной текст `#4c5e55`, заголовки `#123b38`, лесной зелёный `#315d46`, ночной фон `#102f32`, янтарный акцент `#efb35b`. Палитры `garden` и `lantern`, а также семантические переменные Nuxt UI находятся в `app/assets/css/main.css`; настройки компонентов — в `app/app.config.ts`.

Используйте `primary` для зелёных действий и `secondary` для главного акцента. У янтарной кнопки тёмный текст `garden-950`; белый текст на таком фоне не используется. Семантические `error`, `success` и `warning` сохраняют своё значение. Тёмные секции лендинга и боковой блок авторизации используют кремовый текст, а формы остаются светлыми. Это одна тема с контрастными секциями, без переключателя тёмного режима.

Заголовки используют Georgia, интерфейс — Segoe UI с системными запасными шрифтами. Внешние шрифты не загружаются. Крупные заголовки адаптируются через `clamp`; формы сохраняют размер текста 16px на телефоне. У ссылок и кнопок виден фокус клавиатуры. `prefers-reduced-motion` отключает плавную прокрутку и повторяющиеся анимации.

## Первый экран с фоном

Первый экран использует пользовательское изображение `public/images/34a7d373-ee89-4a01-a2e3-7fc7b31039c3.jpg` (1024×572). Оно загружается с высоким приоритетом, заполняет секцию через `object-fit: cover` и имеет пустой `alt`, поскольку служит декоративным фоном. Шапка расположена поверх изображения, текст и действия — в левой нижней части. Старые рамка иллюстрации и демонстрационная карточка из первого экрана убраны.

Палитра лендинга в `app/assets/css/landing.css`: ночной синий `#101e2c`, хвойный `#233f3b`, кремовый `#f8f3e8`, янтарный `#f2bb68`. Затемняющие градиенты поддерживают читаемость текста. На телефоне кадр смещается к дереву, сверху остаётся видимая часть иллюстрации, а действия располагаются друг под другом. Стили ограничены `.landing`; форма входа и canvas используют свою прежнюю компоновку.

## Обновление лендинга 21.10.2026

После первого экрана идут краткие принципы, описание идеи и четыре арочные ссылки в сады. Иллюстрации карточек выполнены на CSS без дополнительных файлов и зависимостей; ссылки используют существующий маршрут `/gardens?garden=…`.

Обновление 23.10.2026: шаги создания размещены на общей светлой поверхности, далее идут принципы, FAQ и приглашение создать место памяти. Пробная форма воспоминания и ссылка на неё удалены. Кнопки создания на первом экране и в завершении ведут на `/gardens`; вход предлагается после выбора свободного места. FAQ объясняет публичность историй и переход к конкретному мемориалу по ссылке. Убраны обещания фотографий, свечей, изменения сада со временем и приватных режимов.

Декоративные светлячки на первом экране двигаются плавно; кнопка с `aria-pressed` приостанавливает движение. Разделы появляются однократно через IntersectionObserver, который отключается при уходе со страницы. Начальное содержимое видно без JavaScript. `prefers-reduced-motion` отключает все анимации лендинга, скрывает светлячков и их переключатель. Изменения не затрагивают тему авторизации и canvas.

## Компоненты интерфейса

- `FormTextField`: поле с подписью, подсказкой, обязательностью, лимитом длины и состоянием `disabled`; `multiline` включает textarea. Ошибки связываются с полем через `UFormField`.
- `AppState`: `kind="loading"`, `kind="error"` или `kind="empty"`; необязательные `title`, `description`, `retry` и событие `retry`. Loading объявляет `aria-busy`, ошибка — `role="alert"`, остальные состояния — `role="status"`.
- `NuxtLoadingIndicator` показывает переход между страницами; `app/error.vue` оформляет 404 и другие ошибки с возвратом на главную.

`AuthShell` и `AuthForm` добавляют страницы регистрации, входа и восстановления в той же теме. Общий shell использует вечерний JPG лендинга: на компьютере слева вступление, справа кремовая карточка формы с янтарной кнопкой; на телефоне короткое вступление и форма в одну колонку. Стили в `app/assets/css/auth.css` ограничены `.auth-page`. Кабинет использует собственную компоновку. Высота полей — от 48px, кнопок и вспомогательных ссылок — от 44px. Однократное появление карточки отключается при уменьшении движения.

Асинхронная загрузка управляется `busy`: форма блокируется, кнопка показывает ожидание. Проверка выполняется при отправке (`validate-on=[]`), чтобы исчезновение ошибки при потере фокуса не сдвигало кнопку под указателем. После ошибки фокус переходит в первое неверное поле. До подключения клиентского кода формы отключены, чтобы ранний клик не потерялся.

Форма создания места памяти находится в саду и описана в [документации создания мемориалов](memorial-creation.md). Иллюстрация `public/images/garden.svg` сохранена как ресурс, страницы авторизации используют вечерний фон лендинга. Устройство карты описано в [документации карты](garden-canvas.md).

## Проверка

```powershell
corepack pnpm build
corepack pnpm exec playwright install chromium
corepack pnpm test:e2e
```

Playwright запускает собранное приложение на `127.0.0.1:4173`. Требуются PostgreSQL и Mailpit — см. [авторизацию](authentication.md). Проверяются обе локали, компьютер и телефон, переходы по странице, FAQ с клавиатуры, отсутствие формы предпросмотра, начало создания в саду, страница 404 и полный цикл авторизации. Скриншоты и следы неудачных тестов находятся в игнорируемой папке `test-results/`.
