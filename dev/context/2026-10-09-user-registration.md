# Регистрация и вход

## Задача

Реализовать этап авторизации из блока 3 дорожной карты: от регистрации до подтверждённого аккаунта и пустого кабинета. Мемориалы и административный интерфейс остаются отдельными задачами.

## Решение

- Better Auth и Drizzle: пользователи, учётные записи с хешем пароля, сессии, токены восстановления; миграция `0001_gigantic_switch.sql`.
- Регистрация по имени/email/паролю, вход после подтверждения email; SMTP-письма в Mailpit, повторная отправка и восстановление пароля.
- Страницы RU/EN в текущей теме, валидация, доступные сообщения об ошибках и ожидании; защищённый кабинет и выход.
- Серверный `/api/me`, HttpOnly-сессии, запрет повышения роли через пользовательский ввод, лимиты запросов, отзыв сессий при смене пароля.
- Проверка конфигурации при запуске; секрет создан только в игнорируемом `.env`.
- Playwright создаёт отдельную временную БД с миграциями и удаляет только её после прогона. CI получает PostgreSQL и Mailpit.

## Проверка

- Миграция с таблицами авторизации применена к локальной БД.
- `lint`, `typecheck`, production-сборка: успешно.
- Playwright: 23 теста прошли; один повтор серверного сценария на мобильном проекте намеренно пропущен (правила API от размера экрана не зависят).
- RU/EN, desktop/mobile: регистрация, подтверждение и повторная отправка письма через Mailpit, вход/выход, восстановление, отзыв старой сессии и отклонение повторного токена.
- Проверены запрет API без входа, подмена роли/emailVerified, посторонний origin/callback, ошибки сети и регрессии лендинга.
- В процессе проверки исправлен сдвиг кнопки при исчезновении ошибки на blur: авторизационные формы проверяются по submit. Диагностический код удалён.
