# Диагностика 503 при работе с мемориалами на Vercel

## Симптом

`GET https://pet-memoreal.vercel.app/api/gardens/lake/memorials` отвечает 503 `Memorials unavailable`; `/api/health` также отвечает 503 `unavailable`.

## Проверенные факты

- Выполнена только диагностика: публичные HTTP GET и транзакция `READ ONLY` в Neon по настройкам игнорируемого `.env.vercel`. Секреты и пользовательские истории не выводились.
- Подключение к базе работает. Присутствуют записи `common`, `meadow`, `lake`, `grove`, `hill`.
- В `memorials` отсутствует столбец `is_anonymous`. Журнал Drizzle содержит пять записей, соответствующих миграциям `0000`–`0004`; `0005` и `0006` ещё не применены к проверенной базе.
- Текущий код использует `memorials.is_anonymous` при чтении списка и создании записи. Ошибка SQL скрывается за общим 503, поэтому регистрация может работать, а операции с мемориалами — нет.

## Исправление

Проверить, что `.env.vercel` и Production-переменные Vercel указывают на одну Neon-базу, и применить подготовленные миграции:

```powershell
corepack pnpm db:migrate:demo
```

`0005_chubby_starfox.sql` добавит `is_anonymous`, сохраняя анонимность прежних записей. `0006_smiling_sharon_carter.sql` ограничит роли значениями `user`/`admin`. Четыре сада уже созданы, повторный seed для устранения этой ошибки не требуется.

После миграции проверить `/api/health` (200), чтение мемориалов и создание с авторизованной сессией. Удалённые миграции, seed, публикация и push в рамках диагностики не выполнялись.
