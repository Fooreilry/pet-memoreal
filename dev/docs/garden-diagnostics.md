# Диагностика PixiJS-садов

## Включение и панель

По умолчанию диагностика выключена. Для локального запуска:

```powershell
$env:NUXT_PUBLIC_GARDEN_DIAGNOSTICS = 'true'
corepack pnpm dev
```

В production задайте эту переменную окружения при запуске сервера или в Vercel и перезапустите deployment. Runtime-флаг работает с обычной production-сборкой; отдельная debug-сборка не требуется. Для выключения удалите переменную или задайте `false`.

Флаг делает инструмент доступным, но **не запускает запись**: начальное состояние — `idle`, `recording=false`. Кнопка со спидометром только открывает панель. Видимость панели, режим отображения и запись — отдельные состояния. `Panel` показывает метрики с обновлением дважды в секунду только при открытой панели и видимой вкладке. `Collect` скрывает текущие таблицы и не запускает периодическое обновление UI; управление записью, результаты и JSON остаются доступны. Открытие и закрытие не переключают режим и не включают запись.

`Начать запись` создаёт run с уникальным ID и меткой сценария. Повторный запуск сохраняет предыдущий run и начинает новый; `Остановить и сохранить` завершает запись. В состоянии `idle` или после остановки обычный рендер работает, но измерительные часы и обработчик результатов рендера не вызываются. Лимит ticker по умолчанию — 30; явно выбранные 60 действуют до ухода со страницы. Выбор FPS сам по себе запись не запускает.

Изменение режима, лимита, seed, эффектов, размеров viewport или видимости панели во время ручной записи сохраняет текущий run с причиной завершения и продолжает запись отдельным run. Так UI-нагрузка и другие условия не смешиваются в одной выборке. Если запись остановлена, изменение условий не запускает её снова. Незавершённые замеры подготовки сбрасываются на границе run.

При выключенном флаге нет коллектора, измерительных буферов, периодического опроса, диагностического API или подмены метода renderer. Доступность диагностики не меняет обычный лимит 30.

## Результаты и формат отчёта

На странице хранится не больше **12 завершённых результатов**; уход со страницы удаляет этот локальный архив. Остановленный результат содержит замороженные показатели, условия начала, время завершения и `endReason`. Последующие кадры, настройки и новая запись его не изменяют. Панель показывает время, частоту рендера, p95 CPU и результат проверки условий. Невалидный или отменённый прогон сохраняет свою причину и не выдаётся за сопоставимый baseline.

JSON версии `schemaVersion: 2` содержит `status`, `recording`, `configuration`, счётчики, метрики и ограниченные сырые выборки. `configuration` фиксирует условия начала, включая видимость панели. Экспортируемый `context` сохраняет измеряемые лимит, seed и размеры; название погодной темы соответствует конечному саду, поскольку сценарий переходов намеренно меняет локации. Отдельный `observedContext` содержит фактическое состояние в конце, чтобы обнаруживать, например, отказ погодного shader вместо незаметной подмены условий. `validation.valid/reasons` описывает проверку контрольного прогона. В `validation.inputKind` сохраняется происхождение ввода для сценария указателя.

Кнопка результата скачивает именно этот run. Общая кнопка скачивает текущую запись либо последний завершённый результат. Имена питомцев, истории, сведения об авторах и данные авторизации автоматически не собираются. Метку сценария вводит сам пользователь; не помещайте в неё личные данные.

## Значение метрик

- `ticks/s` — вызовы обновления активной анимации; `renders/s` — успешные вызовы основной сцены в активное время, **не показанный браузером FPS**. `rates.current` использует последние непрерывные активные 2 секунды или более короткое доступное окно. `rates.average` — весь run; прежние поля `rates.ticksPerSecond/rendersPerSecond` остаются его совместимыми псевдонимами.
- Интервалы ticker измеряются `performance.now()`. Ограниченный `deltaMS` остаётся только входом существующей анимации.
- CPU обновления и CPU вызова рендера измеряются отдельно; завершение работы GPU не измеряется. Ручные кадры учитываются, в том числе при паузе, в отдельных счётчиках и `allRenderCpu`. Проходы кешей и снимок в RenderTexture не считаются дополнительными кадрами основной сцены.
- Активное время исключает паузу, уменьшение движения, переходы, скрытую вкладку и offscreen. Первый интервал после возобновления начинает новую непрерывную серию.
- Генерация — синхронная работа создания геометрии сцены и окружения. Подготовка — от начала подготовки до геометрии, кешей и первого кадра, включая generation, но без ожидания API и проявления. `totalReadyMs` — полный путь от запроса сцены до доступного интерфейса, включая переход и API. Эти интервалы перекрываются: их нельзя суммировать.
- API измеряется вокруг конкретного запроса; открытие памятника и resize не повторяют прежнюю задержку сети. `rebuilds` считает полные map/detail factories за текущий run. Объекты и кеши — инвентаризация живого графа, **не видеопамять**.

Для каждого типа измерений хранится до 2048 значений. p50/p95/p99 — nearest-rank по сохранённой выборке; totals/mean/min/max относятся ко всему run. Текущее окно очищается на паузе и при скрытии; остановка сохраняет его последнее значение. В отчёте есть реальные размеры viewport/backing, DPR, resolution, seed, эффекты, лимит, дата, build ID при наличии и описание методики. Задайте `GARDEN_BUILD_ID` при сборке или `NUXT_PUBLIC_GARDEN_BUILD_ID` при запуске для своего идентификатора; Vercel commit SHA подхватывается при сборке.

## Контрольный прогон из интерфейса

Выберите сценарий и область: текущий сад либо все четыре. Доступны неподвижная камера с погодой и без неё, непрерывное движение камеры, указатель/колесо, переключение садов, подготовка сцены и полный набор. Для обычного сценария применяется общий протокол: seed 424242, **3 секунды прогрева, 15 секунд измерения, 3 повтора на сад**. Подготовка и серия переключений имеют отдельные действия и проверки; полный набор занимает несколько минут.

Панель показывает фазу (`warming`, `measuring`, `switching`), повтор и число сохранённых результатов. Конфликтующие настройки заблокированы. `Отменить прогон` останавливает выполнение; закрытие панели, пауза, скрытие вкладки или сцены также отменяет его, сохраняя одинаковые условия эксперимента. Отмена до начала измерения не создаёт пустой результат; прерванная запись отмечается невалидной. Состояние сада после прогона восстанавливается. Результаты доступны в том же локальном архиве.

Автопрогон UI вызывает существующие обработчики через **синтетические события** и маркирует их `synthetic-events`. Внешний Playwright-прогон использует доверенные события браузера и метку `trusted-playwright`. Их нельзя считать одинаковой проверкой физического ввода. Обе версии используют общие траектории и проверяют фактически обработанные pointer/wheel и выполненные кадры. Условия внешнего прогона описаны отдельно в [garden-benchmarks.md](garden-benchmarks.md).

## Проверки и воспроизводимые замеры

```powershell
corepack pnpm build
corepack pnpm test:diagnostics
corepack pnpm bench:gardens
```

Условия, сценарии и расположение baseline описаны в [garden-benchmarks.md](garden-benchmarks.md). Во время полного бенчмарка не запускайте сборки и другие браузерные проверки.
